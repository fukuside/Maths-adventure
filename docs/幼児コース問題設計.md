# Maths-Adventure 幼児コース問題設計 v1

作成日：2026年10月12日。設計案であり、問題の実装・有効化はまだ行っていません。

## 基本方針

幼児コースは、小学生コースへ進む前に、数・形・比較・規則・位置に親しむ独立コースとします。対象年齢で一律に難度を決めず、K1から順に遊べる構成にします。年齢の入力・成績による自動コース移動は設けません。

- 6WORLD × 通常6ステージ＋まとめ1ステージ＝42ステージ。
- 通常・まとめとも5問ランダム。1画面に1つの問いを出します。
- 最初は2択、慣れてから3択。選択肢の絵を直接タップして答えます。
- 問題は常時表示。時間制限・フラッシュ暗記・数字の自由入力は使いません。
- 問いは短いひらがな＋絵。数字や形も回答に使います。
- まとめは新しい内容を出さず、そのWORLDで経験した形式を混ぜます。
- コースの進捗は既存のプレイヤーに保持し、新しい幼児用ステージIDで区別します。

初版の練習では、間違えても同じ問題を続けられる方式を推奨します。「もういちど みてみよう」と伝え、2回目以降は数える順序や比較の基準線などのヒントを表示します。これは現在の3バリア制からの幼児限定変更案であり、実装時には小学生側を維持して分岐させます。ヒント利用を失敗扱いせず、通常の正答記録と区別できる設計にします。

## 問題例とデータ

K1-S3：「いくつ ある？」にりんご3個。候補は2・3・4。並びを変えたあと、正答の候補IDを確定します。

```js
{
  kind: "k-count",
  prompt: "いくつ ある？",
  visual: { icon: "apple", count: 3, layout: "row" },
  choices: [
    { id: "A", label: "2", value: 2 },
    { id: "B", label: "3", value: 3 },
    { id: "C", label: "4", value: 4 }
  ],
  answer: "B",
  uniqueKey: "k-count:apple:3:row:2,3,4"
}
```

visual・value・kindは新しい設計項目です。既存の問題生成は choices と文字列 answer のA/B/Cを扱えますが、現在の choice キーパッドは常にA/B/Cの3ボタンです。2択や絵の直接タップを実現するため、幼児専用rendererと回答UIが必要です。数字2を表示していても、内部判定は候補IDのA/B/Cとし、既存の判定経路を利用します。

候補には同じ意味の答えを重複させません。全問で正解は1つ。候補の順序をランダムにしても、答えのIDと絵の対応を維持します。0個は空の枠で示し、表示が消えたように見せません。

## 出題・表示の品質条件

1. 5問を生成できる問題数を確保します。K1-S2は数字が3種類しかないため、絵柄・配置など意味のある違いを用意します。乱数だけの識別子で重複判定を回避しません。
2. まとめは6形式から5形式をランダムに選び各1問を生成して混ぜ、形式が偏るランダム出題にしません。既存generateQuestionsは1問ずつ生成するため、専用のセット生成対応が必要です。
3. 数える物は重ねず、10個までは画面内で一覧できるようにします。絵のサイズや並べ方で比較の正解が変わる問題は避けます。
4. 形・長さ・天びん・配置はSVGを基本とし、絵文字の端末差で正解が変わらない表示にします。色だけを手がかりにしません。
5. 回答ボタンは48px以上を設計目標とし、スマートフォンの縦画面で問題と全候補が読めることを確認します。48pxはこのアプリの設計値です。
6. 回答は絵を直接タップし、別の「決定」操作を不要にします。連打で二重採点しないようにします。
7. 読み上げは後続の追加候補。初版は短い説明と例題、保護者が読み上げられる問いを提供します。音声がない状態も明示します。
8. 通常・まとめとも正解5問でクリア。同じ問題への再挑戦で進めます。計測するなら初回正答とヒント後正答を分け、所要時間で評価しません。

## 既存アプリとの接続

- パック：src/content/packs/kindergarten/。幼児だけに使う問題生成・表示は配下の generators/ と renderers/ に置きます。
- WORLDの内部ID案：101〜106。表示名はK1〜K6。現在のworld選択がNumberへ変換するため、文字列K1を内部WORLD IDとしてそのまま使いません。
- ステージID案：k1-s1〜k6-s6、k1-boss〜k6-boss。既存ステージIDは維持します。
- コース判定：幼児パックを識別して一覧を分けます。現在、小学生一覧は全worldsを表示するため、幼児パック追加と同時に一覧の絞り込みを実装する必要があります。
- presentation は persistent、questionCount は通常・まとめとも5。まとめは既存のisBossを利用できますが、利用者向け名称は「まとめ」にします。
- 保存キー maths_adventure_state_v1 と maths_adventure_profiles_v1 は維持。新しいステージIDを使い、既存進捗を上書きしません。クラウド記録と引き継ぎの互換性も確認します。
- ジェム数・カード報酬は初版実装で既存処理との接続を確認して決めます。カードの新作がない段階で既存カードを無断で幼児報酬に流用しません。
- 今回モンスター画像は作成しません。後日作成する場合はプロジェクト指定の1080×1080 PNG、全身中央・15〜20％余白・背景あり・文字なし、N→SR→URの同一個体進化を守ります。

## 実装順序と確認

第一段階はK1-S1〜S3を実装し、絵の直接回答・2択／3択・常時表示・再挑戦・小学生側への影響を確認します。続いてK1全体、K2、K3〜K6を追加します。未実装WORLDは準備中のまま維持します。

各ステージで、範囲内の値・正答一意性・候補数・シャッフル後の判定・5問の生成を確認します。まとめの形式配分、スマートフォン表示、再読み込み後の進捗、クラウド保存、引き継ぎ、既存小学生問題の動作を別に確認します。

この設計は会話で合意した幼児6WORLD構想と現在のコードをもとにしたアプリ仕様案です。教育課程への適合や年齢別の到達保証を主張するものではありません。
